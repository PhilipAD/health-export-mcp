Connect Apple Health to ChatGPT via Webhook — Your Data, Their Agent

ChatGPT is the most-used AI agent in the world, but it has a blind spot: it can't speak Model Context Protocol (MCP). No MCP means no native access to health-export-mcp's seven query tools — no "What's my HRV trend?" over stdio.

But ChatGPT does support Actions — an OpenAPI-based integration system inside Custom GPTs — and the Health Export AI iOS app exports your Apple Health data to any HTTP endpoint via token-authenticated webhook. Put those two together and you can ask ChatGPT any question about your actual health data.

Here's the complete setup, start to finish.

How the webhook flow works

The architecture is three pieces that snap together:

  1. Health Export AI (iOS) — reads 190 Apple Health metrics (HRV, sleep stages, resting heart rate, steps, VO₂ max, workouts, and more) and POSTs them as JSON to a webhook URL you configure.
  2. Your webhook receiver — a lightweight HTTP endpoint that accepts the POST, validates the token, and stores the data. The health-export-mcp server's built-in receiver.mjs does exactly this.
  3. Your Custom GPT — a ChatGPT agent with an Actions configuration that defines GET endpoints your GPT can call to query the stored data.

The data stays where you put it. Your health data goes directly from your iPhone to your endpoint — no third-party relay.

Prerequisites

  • An iPhone with Apple Health data (even a few days of steps or sleep is enough)
  • The Health Export AI app installed from the App Store
  • A machine running Node.js ≥ 18 (your Mac, a cloud VM, or a Raspberry Pi on your LAN)
  • A ChatGPT Plus or Pro account (Custom GPTs with Actions)
  • A way to expose your receiver to the internet — ngrok or Cloudflare Tunnel for local, or deploy to Railway / Fly.io for always-on

Step 1 — Run the webhook receiver

The health-export-mcp server ships with a zero-dependency HTTP/WebSocket receiver (receiver.mjs) that accepts the iOS app's push. Start it with the HEALTH_LISTEN flag:

git clone https://github.com/PhilipAD/health-export-mcp.git
cd health-export-mcp

# Start the MCP server + receiver together
HEALTH_LISTEN=1 HEALTH_LISTEN_TOKEN=your-secret-token \
  HEALTH_DATA_DIR=~/.health-export-cache \
  node server.mjs

This starts the receiver on 127.0.0.1:27184 by default. The server logs to stderr (so it doesn't interfere with the MCP stdio stream):

[receiver] listening on 127.0.0.1:27184

For ChatGPT to reach it from the internet, tunnel that port:

ngrok http 27184
# → https://abc123.ngrok-free.app

Your webhook URL is https://abc123.ngrok-free.app/health-cache.

Security note: When binding to a non-loopback interface, receiver.mjs refuses to start unless HEALTH_LISTEN_TOKEN is set. The iOS app sends this as the X-Health-Token header, and the receiver compares it in constant time. Use the same pairing code from the iOS app's Settings → Agent pairing.

Step 2 — Configure the iOS app

Open Health Export AI on your iPhone and go to Destinations → Webhook:

  1. URL: paste your receiver URL (https://abc123.ngrok-free.app/health-cache).
  2. Token: enter the same token you set in HEALTH_LISTEN_TOKEN.
  3. Toggle the webhook destination on.
  4. Tap Test — the app sends a sample payload. You should see [receiver] merged N metrics in your server logs.

Once verified, the app will automatically POST your full health cache on every sync cycle (typically every 30 minutes, or immediately when new data arrives from HealthKit).

Step 3 — Create the ChatGPT Actions endpoint

The receiver accepts writes but doesn't expose a query API. You need a lightweight HTTP endpoint that reads the cached file and returns answers. Here's a minimal Express server that does the job — create chatgpt-bridge.mjs in the repo root:

import { readFileSync } from 'node:fs';
import express from 'express';

const DATA = readFileSync(process.env.HEALTH_DATA_DIR + '/.health-cache.json', 'utf8');
const cache = JSON.parse(DATA);

const app = express();

// List all available metrics
app.get('/api/metrics', (req, res) => {
  const names = Object.keys(cache).sort();
  res.json({ metrics: names, total: names.length });
});

// Get daily values for one metric
app.get('/api/metrics/:name', (req, res) => {
  const m = cache[req.params.name];
  if (!m) return res.status(404).json({ error: 'metric not found' });
  res.json({ name: req.params.name, unit: m.unit, daily: m.daily });
});

// Trend: last 7 days vs the 7 before
app.get('/api/trends', (req, res) => {
  const results = {};
  for (const [name, m] of Object.entries(cache)) {
    const d = [...m.daily].sort((a, b) => a.d.localeCompare(b.d));
    const recent = d.slice(-7).reduce((s, p) => s + p.v, 0) / 7;
    const prior = d.slice(-14, -7).reduce((s, p) => s + p.v, 0) / 7;
    results[name] = { recent, prior, change: recent - prior, unit: m.unit };
  }
  res.json(results);
});

app.listen(3000, () => console.log('bridge on :3000'));

Run this bridge alongside your receiver, and expose it through the same ngrok tunnel (or a second one on port 3000).

Step 4 — Build the Custom GPT

In ChatGPT → Explore GPTs → Create a GPT:

  1. Name: "Health Analyzer" (or whatever you like).
  2. Description: "Queries my Apple Health data exported from the Health Export AI app."
  3. Instructions: paste the following system prompt:
You have access to a user's Apple Health data through the Health Export AI
Actions API. When asked about health metrics, call the appropriate endpoint
and present the results clearly.

- Use /api/metrics to see what's available.
- Use /api/metrics/{name} for daily values of a specific metric.
- Use /api/trends to compare recent vs prior periods.

Always say the actual numbers from the response. Do not invent data.
  1. Actions → Import from URL or paste this OpenAPI spec:
openapi: 3.0.0
info:
  title: Health Export AI Bridge
  version: 1.0.0
servers:
  - url: https://abc123.ngrok-free.app
paths:
  /api/metrics:
    get:
      summary: List all available health metrics
      operationId: listMetrics
      responses:
        '200':
          description: Array of metric names
  /api/metrics/{name}:
    get:
      summary: Get daily values for one metric
      operationId: getMetric
      parameters:
        - name: name
          in: path
          required: true
          schema: { type: string }
      responses:
        '200':
          description: Daily values with unit
  /api/trends:
    get:
      summary: Get 7-day trend comparison
      operationId: getTrends
      responses:
        '200':
          description: Recent vs prior period averages

Save the GPT. It's now wired to your health data.

Step 5 — Ask your health data questions

Open the Custom GPT and try these queries:

  • "What metrics are available in my health data?"
  • "Show me my average resting heart rate over the last 2 weeks."
  • "Compare my deep sleep this week vs last week."
  • "Is my HRV trending up or down this month?"
  • "What's my step count trend and how does it correlate with my sleep?"

Each query calls the bridge API, reads the cached health data, and returns real numbers from your Apple Health export. The same 190 metrics available through MCP — heart rate, HRV, sleep stages, VO₂ max, walking speed, blood glucose, mindful minutes, and more — are all accessible through the webhook pipeline.

Alternative: Use ChatGPT with a file upload

If you don't want to set up a receiver and bridge, there's a simpler path: the Health Export AI app can save the health cache to iCloud Drive. Download that file (.health-cache.json) and upload it directly to a ChatGPT conversation:

"Here's my Apple Health export. Analyze my sleep trends over the last 30 days."

ChatGPT's code interpreter reads the JSON and answers. You lose real-time updates and the natural-language repeatability of a Custom GPT, but for a one-off analysis it works immediately with zero infrastructure.

Troubleshooting

  • 401 Unauthorized from receiver — the HEALTH_LISTEN_TOKEN in your server must match the token in the iOS app's webhook destination. They're compared as SHA-256 hashes via constant-time comparison.
  • "No metrics found" from the bridge — confirm the iOS app has exported at least once. Check .health-cache.json exists in your HEALTH_DATA_DIR.
  • ngrok tunnel expired — free ngrok sessions time out after 2 hours and the URL changes on restart. For persistent access, deploy the receiver to Railway or Fly.io, or use a Cloudflare Tunnel with a fixed DNS name.
  • ChatGPT says "Action returned an error" — the bridge must be reachable from ChatGPT's servers (public HTTPS). Verify the tunnel is up and the OpenAPI spec's servers.url matches your tunnel URL exactly.

What you can do with health data in ChatGPT

Once the pipeline is running, you have access to the same 190 Apple Health metrics that health-export-mcp serves to MCP clients. Here are real use cases that work today:

  • Training load analysis — ask ChatGPT to pull your VO₂ max, running pace, and heart rate recovery across this quarter vs last quarter. See progression plotted against your logged workouts.
  • Sleep pattern tracking — "Show me a table of my deep sleep percentage for each of the last 14 days. Highlight days where I got less than 20% deep sleep in red." ChatGPT can render formatted tables and charts from the raw JSON.
  • HRV and recovery — "What's my average HRV this week? Compare it to my resting heart rate over the same period. Tell me if my recovery trend is improving."
  • Nutrition correlation — if you log dietary calories or caffeine in Apple Health, ask: "Does my HRV correlate with my caffeine intake on the same day?"

Because ChatGPT can render charts and tables (not just text), the webhook bridge actually gives you richer output than a pure-MCP interface for some queries. Use it for visualization alongside the MCP clients for structured data analysis.

Frequently Asked Questions

Can ChatGPT read my Apple Health data directly?

Not natively — ChatGPT doesn't support the Model Context Protocol that MCP servers use. But it does support Custom GPTs with Actions, which can call HTTP endpoints. The webhook bridge described in this guide turns your Apple Health export into an API that ChatGPT Actions can query.

Do I need to keep my computer running all the time?

For real-time access, yes — the receiver needs to be running to accept webhook pushes. If you want always-on access, deploy the receiver to a cloud service like Railway or Fly.io. For occasional analysis, you can skip the receiver entirely and upload the exported JSON file directly to a ChatGPT conversation.

Is my health data sent to Health Export AI's servers?

No. The webhook POSTs directly from your iPhone to the endpoint you configured. The health-export-mcp server and receiver are open-source software you run yourself. There is no developer server in the path — the data goes from your device to your endpoint and nowhere else.

Which Apple Health metrics are available through the webhook?

All 190 metrics that Health Export AI reads from Apple HealthKit — the same set available through the MCP server. This includes heart rate, HRV, resting heart rate, sleep stages (deep, core, REM), steps, walking + running distance, VO₂ max, environmental sound levels, mindful minutes, and workout data.
