Connect Apple Health to ChatGPT via Webhook — Your Data, Their Agent

ChatGPT's new features — Actions, Custom GPTs, and the conversational agent interface — mean you can ask questions about your health data in plain English and get answers drawn from your real Apple Health records. The missing piece has always been getting the data into ChatGPT in the first place.

This guide walks through the practical setup: Health Export AI's webhook integration sends your Apple Health metrics to any URL you specify, and you configure ChatGPT to receive and query that data. No export.xml, no DuckDB, no manually maintained CSV files. Everything syncs automatically from your iPhone.

What you'll build

By the end of this guide you'll have a Custom GPT that can answer questions like:

  • "What was my average HRV over the last week?"
  • "How has my resting heart rate changed compared to last month?"
  • "Show me my sleep trends for the past 7 days — time in bed vs. time asleep."
  • "What's my step count trend this quarter?"

The answers come from your actual Health Kit data, synced automatically every 30 minutes from your iPhone.

The architecture

The setup has three parts:

  1. Health Export AI (iOS app) — reads 190 metric types from HealthKit and sends a structured JSON payload to a webhook URL of your choice, on a configurable schedule.
  2. A webhook receiver — a serverless endpoint (or your own server) that receives the payload and stores or indexes it. In this guide we'll use a simple serverless function deployed on Cloudflare Workers or Vercel.
  3. A ChatGPT Custom GPT — configured with an Action that points at your webhook receiver's query endpoint.

The Health Export AI app handles the iOS-side encryption, scheduling, and data shaping. The companion health-export-mcp server provides the same data over stdio for desktop MCP clients — the webhook path is the cloud-native equivalent for ChatGPT.

Step 1: Enable webhook sync in Health Export AI

Open the Health Export AI app on your iPhone. Tap the gear icon to open Settings, then tap Webhook.

You'll see a configuration screen with three inputs:

Webhook URL:   https://your-endpoint.example.com/health-ingest
Secret Token:  whsec_your_secret_token_here
Sync Interval: 30 minutes

The webhook URL is where the app sends the data payload every cycle. The secret token is sent as an Authorization: Bearer header so your receiver can verify the payload came from your phone. The sync interval controls how often the app pushes data — 30 minutes is the default, and the minimum interval avoids excessive battery use on the HealthKit background fetch.

Once configured, the app immediately sends a full payload snapshot, then continues on the schedule. You can verify it's working by checking the Sync Log in the same settings screen — each entry shows the sync time, the number of metrics included, and the response status code from your webhook receiver.

Step 2: Receive the webhook payload

You need an endpoint that accepts POST requests. Here's a minimal Cloudflare Worker that receives the payload and stores it, then exposes a query endpoint for ChatGPT:

export default {
  async fetch(request, env) {
    const url = new URL(request.url);

    // Verify webhook signature
    const token = request.headers.get("Authorization")?.replace("Bearer ", "");
    if (token !== env.SECRET_TOKEN) {
      return new Response("Unauthorized", { status: 401 });
    }

    if (request.method === "POST" && url.pathname === "/ingest") {
      // Receive and store the health data payload
      const payload = await request.json();
      await env.HEALTH_KV.put("latest", JSON.stringify(payload));
      return new Response("OK", { status: 200 });
    }

    if (request.method === "GET" && url.pathname === "/query") {
      // Return the latest snapshot for ChatGPT to read
      const data = await env.HEALTH_KV.get("latest");
      return new Response(data, {
        headers: { "Content-Type": "application/json" }
      });
    }

    return new Response("Not Found", { status: 404 });
  }
}

Deploy this as a Cloudflare Worker, set SECRET_TOKEN as an environment variable, and point the app at https://your-worker.workers.dev/ingest.

You can also use Vercel Serverless Functions, AWS Lambda, or any HTTP endpoint — the app sends a well-formed JSON payload and expects a 200 response. The data format is the same .health-cache.json format used by the MCP server:

{
  "version": 1,
  "exportedAt": "2026-07-26T12:00:00Z",
  "metrics": {
    "HeartRateVariabilitySDNN": {
      "unit": "ms",
      "data": [
        { "date": "2026-07-25", "value": 48.2 },
        { "date": "2026-07-24", "value": 52.1 }
      ]
    },
    "RestingHeartRate": {
      "unit": "count/min",
      "data": [
        { "date": "2026-07-25", "value": 58 }
      ]
    },
    "StepCount": { "unit": "count", "data": [ ... ] },
    "AppleSleepingWristTemperature": { "unit": "degC", "data": [ ... ] }
  }
}

Each metric includes its unit and daily aggregate values — same structure whether you're consuming it via MCP on desktop or via webhook for ChatGPT.

Step 3: Create the Custom GPT with an Action

Open ChatGPT and navigate to Explore GPTs → Create. Give your GPT a name like "Health Stats" and a description. In the Instructions field, add guidance so the GPT uses the webhook data naturally:

You are a personal health analytics assistant. You have access to the user's
Apple Health data via an API endpoint (GET /query).

When the user asks about their health metrics:
1. Call /query to get the full dataset.
2. Find the relevant metric key by matching the user's question to the metric
   names in the payload.
3. Return the data with context — trends, comparisons to the prior period,
   and deviations from the user's personal baseline.

Available metrics vary per user but include HRV, resting heart rate, steps,
sleep, active energy, and more. Always check all metric keys before saying
a metric isn't available.

Now configure the Action. Click + New Action and paste this OpenAPI schema:

openapi: 3.1.0
info:
  title: Health Export API
  version: "1.0"
servers:
  - url: https://your-worker.workers.dev
paths:
  /query:
    get:
      operationId: getHealthData
      summary: Get all Apple Health data
      description: Returns the latest snapshot of all health metrics
      responses:
        "200":
          description: Health data payload
          content:
            application/json:
              schema:
                type: object

ChatGPT's Actions runtime will automatically call this endpoint when the GPT's instructions tell it to. No authentication is needed for the query endpoint if your worker only exposes /query without a signature check — or you can add an API key in the Action's authentication section for extra protection.

Step 4: Ask your health questions

Once the GPT is configured, the flow looks like this:

You: "What's my HRV been doing this week?"

GPT: (calls /query, inspects HeartRateVariabilitySDNN) "Your HRV this week averaged 48 ms, which is within your personal baseline range. Your highest reading was 56 ms on Monday, and your lowest was 42 ms on Thursday — a typical variation for active recovery days."

Because ChatGPT processes the entire payload, it can answer cross-metric questions too: "How does my resting heart rate correlate with my sleep time this month?" or "Show me days where my step count was below 5,000 and my HRV was below 40 ms."

Privacy considerations

This architecture means your health data leaves your iPhone — it's sent to your webhook receiver over HTTPS, and then fetched by ChatGPT's Action runtime. Here's what that means in practice:

  • You control the receiver. Deploy it on your own Cloudflare account, your own AWS account, or your own server. No third-party cloud processes your data.
  • Data is encrypted in transit. HTTPS from the app to the receiver, and HTTPS from ChatGPT to the receiver.
  • OpenAI sees only what the Action returns. If you deploy the worker above, ChatGPT fetches the whole payload on every query. You can minimize exposure by routing through a middleware that returns only the metrics the user asked about.
  • No manual export. Unlike XML-based approaches, there's never an export.xml sitting in your Downloads folder or uploaded anywhere.

The companion health-export-mcp server offers a fully local alternative for users who want to keep data entirely on-device. The webhook path is strictly for scenarios where you want ChatGPT to have agentic access to your numbers — and you control the endpoint that mediates that access.

Troubleshooting

Webhook sync shows "401" in the sync log. Your secret token doesn't match what the receiver expects. Verify the Authorization header comparison in your receiver code.

ChatGPT says "I don't have access to your health data." The Action schema may not be connected. Check that the GPT's Action section has the correct OpenAPI spec and your worker's URL is correct. Also confirm the worker's /query endpoint returns a 200 with JSON.

Not all metrics appear in the payload. Health Export AI only sends metrics that have data in the sync window. If you just started wearing your Apple Watch, it may take a day for metrics like HRV and resting heart rate to populate. The MCP server's list_metrics tool can show you exactly which metrics are populated.

The payload is too large for ChatGPT's Action context. The full health cache for a typical user is 15-30 KB — well within ChatGPT's per-request limits. If you have years of history, consider returning only the last 90 days from your receiver to keep responses snappy.
